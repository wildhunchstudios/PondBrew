# Game Session Handoff

Read canonical AGENTS.md current state and Git status. Keep it the single live roadmap. Docs/TASKS.md, RESUME.md and VALIDATION.md are historical evidence; append records when the assignment warrants them, not a competing dashboard. Docs/tooling/INSTALL_REPORT.md and toolchain-lock.json track tooling only.

Inputs: requested scope, baseline commit/worktree edits, ownership, changed files, executed commands/results and open gates. Preserve the approved front-shop/back-lab design, Unity pin, existing build and user's normal save. Never access/import from Dungeon or PersonalAssistant. No reset, history rewrite, automatic engine upgrade, remote push or paid generation follows from continuation.

Before closing, review the diff against the request. For gameplay review, trace stock ownership, reservation/payment order, duplicate/interrupted commands, save version/legacy recovery and presentation failures. For presentation review, inspect actual captures and root/collider/material ownership. For tooling review, distinguish installed/registered/authenticated/working, check selected process/project identity and limit external-data scope. Use an independent reviewer only where useful and authorized; agent reports require inspection.

Run checks proportional to the actual change. Record command, source/build identity, exit code, counts and raw evidence path. Preserve failed attempts and explain any fix; never relabel historical passes as current tests. Documentation/skill changes do not require a new full game build. New helper scripts must actually run or be labelled untested.

Update AGENTS.md after every completed assignment with status, exact evidence, known issues and next executable step. Save a small local Git checkpoint of only the owned verified change, without including credentials, environments, temporary exports or user edits. List pending approval/authentication separately from technical failures.

Output: what changed, actual validation, relevant playable/artifact link and controls, checkpoint, limitations and the next bounded task. Keep creative acceptance distinct from technical success and do not advance R07 while the R06.5 feedback gate is open. A setup report never means the game is finished.
